# 涼道ナビTOKYO

都知事杯オープンデータ・ハッカソン2026向けのMVPです。

## 起動

```bash
npm install
npm run start:local
```

`npm run start:local` は、Worker を先に起動してから Frontend を起動し、オープンデータの取得ができる状態を作るためのコマンドです。

手動で起動する場合は、別ターミナルで Worker を起動してから Frontend を起動します。

```bash
npm run worker:dev
npm run start:frontend
```

このプロジェクトのローカル固定ポートは次の通りです。

- フロントエンド Vite: `5174`
- API Worker: `8788`

このリポジトリにはローカル用の設定ファイルとして [.env.local](.env.local) と [.dev.vars](.dev.vars) を入れてあります。
前者はフロントから Worker を見るための URL、後者は Worker 側のローカル変数です。
OpenRouteService の実ルートを使うには、[.dev.vars](.dev.vars) の `ORS_API_KEY` を自分のキーで埋めてください。

## 主な機能

- 現在地モード / デモ保証エリア（江東区）モードの手動切り替え
- クーリングシェルターの地図表示
- 東京都オープンデータからのシェルター・街路樹・公園・給水スポット取得
- 施設スタッフ用の空き状況更新画面
- 任意目的地へのルート比較
- 街路樹・公園・給水スポットを使った緑陰スコア
- 江東区デモ限定の建物日陰参考レイヤー
- WBGTを想定した熱中症リスク表示

## 2026/08/12 更新: 仕様と使い方の整理

このアプリは、暑い日でも安心して歩けるルートを見つけるための地図アプリです。
江東区を中心に、涼しさにつながる情報を地図上で確認できるようにしています。

### できること

- 地図で現在地や江東区の範囲を確認できる
- クーリングシェルターの場所を見られる
- 近くの木や公園、休める場所をチェックできる
- 給水スポットの位置を見られる
- 目的地の候補を比較できる
- 施設の空き状況を更新できる
- 熱中症の危険度を、簡単な目安として見ることができる
- 江東区限定の「建物の影の目安」を参考に、日陰の入りやすさを確認できる

### 実際の使い方

- 現在地モード
  - 自分の位置に近い情報を見たいときに使う
  - 実際の位置情報が使える場合に表示が変わる
  - 位置情報が取れないときは、東京都心を基準に表示する
- デモ保証エリア
  - 江東区を中心に、動作確認しやすいようにしているモード
  - 開発中やデモ用に使う想定
  - 計算や表示を安定して確認しやすい
- 建物の影の目安
  - 地図上のボタンで表示・非表示を切り替えられる
  - 参考として、日陰になりやすい場所を見ることができる
- 空き状況の更新
  - 施設の空き情報を更新する画面がある
  - スタッフ向けの確認操作として使う前提

### まだ未実装の部分

以下は、UI 上には出ているものの、まだ実際には完璧に動作していない、または確認中の機能です。

- 検索機能
  - 検索欄は見えているが、検索処理はまだ十分に動作していない
  - 目的地の入力からルートへつながる流れは、今後の実装対象
- ルートの実運用
  - ルート候補は表示できるが、完全な実利用向けの経路計算はまだ簡易な形が中心
  - 参考の経路表示が主で、利用場面に応じて補正が必要
- スタッフ画面の本格運用
  - 空き状況の更新画面はあるが、現時点ではローカル確認用の前提
  - 本番相当の運用や保存方法は未確定
- 位置情報の正確性
  - 現在地モードは使えるが、端末の位置情報が取れないときは固定の表示へ切り替わる
  - 実運用では、位置精度や許可状態をもう少し考える必要がある

### オープンデータについて

このアプリでは、東京都や江東区の公開データを使って情報を表示しています。
使っているデータの一覧と内容は、[docs/USED_OPEN_DATA.md](docs/USED_OPEN_DATA.md) にまとめています。
また、データの取得元や調査内容は、[docs/DATA_RESEARCH.md](docs/DATA_RESEARCH.md) にあります。

### ルートの考え方

目的地までの経路は、いくつかの候補を比較できるようになっています。
ただし、外部の経路情報が使えないときは、参考として動く経路を表示する仕組みになっています。
そのため、実際の経路が使えない場合でも、アプリは動くように作られています。

### 仕組みの大事なポイント

- 画面を表示する部分と、データを受け取る部分が分かれている
- データが取得できないときは、開発用のサンプル情報で代わりに表示する
- 画面では「本物のデータ」と「参考データ」の両方に対応している
- そのため、開発中や確認中に、アプリが止まらずに動いて見えるようになっている

## スタッフ更新画面

```text
/staff/koto-001
/staff/koto-002
/staff/koto-003
```

現時点ではローカルデモ用にブラウザ内状態で更新します。Cloudflare Workers + D1 用のAPIとスキーマも用意しています。

## オープンデータ

Worker の `/api/open-data/:kind` が東京都系CSVを取得し、Shift_JISからUTF-8へ変換してフロントへ返します。対応する `kind` は `shelters`, `trees`, `parks`, `water` です。取得できない場合はデモ用データにフォールバックします。

## 建物日陰

地図上の「建物日陰の目安」ボタンで、江東区デモ限定の参考レイヤーを表示できます。PLATEAU 3D都市モデルの江東区建築物LOD1から、東陽町〜木場〜南砂周辺の建物矩形と高さを抽出して使用しています。現時点では固定日時の影ポリゴンを表示し、ルートと重なる建物日陰の推定割合を緑陰スコアに反映しています。

PLATEAU建物データを再生成する場合:

```bash
npm run data:plateau-buildings
```

## 歩行ルート

本番想定では `VITE_API_BASE_URL` と Worker 側の `ORS_API_KEY` を設定すると、OpenRouteService Directions API の `foot-walking` で実際の歩行ルートを取得します。

ローカル検証を簡単にする場合は、`.env.local` に `VITE_ORS_API_KEY` を設定すると、Workerを起動せずにブラウザからOpenRouteServiceへ直接問い合わせます。これはデモ検証用で、公開環境ではAPIキー保護のためWorker経由にしてください。

未設定時はデモ用の参考ルートにフォールバックし、画面にもその旨を表示します。

## 環境変数

- `VITE_API_BASE_URL`
- `VITE_ORS_API_KEY`
- `ORS_API_KEY`
- `STAFF_UPDATE_TOKEN`
- `AI_API_KEY`

APIキーはリポジトリにコミットしません。
